# DLV Automation — откуда поисковая аудитория avtomatika.ru и что перенимаем
Дата анализа: 22.10.2026. Задача: привлекать заявки на **программирование PLC/SCADA и интеграцию промышленных систем**, а не абстрактную массовую аудиторию.

## 1. Что удалось проверить (без выдуманных визитов)

1. **Поисковая видимость Яндекса, не фактический трафик.** Независимый публичный срез GO SERP по `avtomatika.ru` из Букварикса за август 2026: **32** запроса на 1-й позиции, **44** в топ-3, **156** в топ-10 и **181** в топ-20. По графу Common Crawl июль–сентябрь указано **52 ссылающихся домена**. Доступные позиции: «что такое сухой контакт в электрике по простому» — 1; «rs 485 интерфейс что это простыми словами» — 1; «какие контроллеры бывают» — 1; «modbus tcp для чайников» — 3; «что такое rs 485 простыми словами» — 8; «протокол связи modbus» — 8. Источник: https://domain.goserp.ru/avtomatika/ . Эти данные не дают достоверного числа посетителей/покупателей и не показывают долю переходов из Google.
2. **Структура привлечения.** У сайта есть блог с десятками тем: RS-485, Modbus RTU, сухой контакт, OPC UA, контроллеры, энкодеры, MQTT, Home Assistant. Есть каталог физических устройств (постоянный спрос по артикулам), онлайн-конструктор/тестовый проект и страницы услуг (PLC, SCADA, MasterSCADA). Источники: https://avtomatika.ru/blog , https://avtomatika.ru/catalog , https://avtomatika.ru/services , https://avtomatika.ru/ .
3. **Коммерческая упаковка.** Страница https://avtomatika.ru/uslugi/programmirovanie-plk содержит сценарии оценки, типы цен, ориентировочные «от» цены и обещание контакта с инженером. Это опубликованные заявления конкурента, мы не проверяли их реальные сроки/стоимость. DLV не должен копировать чужие цены, чужие кейсы или обещания.
4. **Ограничение измерений.** Semrush Organic Research и Competitors Research недоступны из-за отсутствия API units, а Semrush Traffic Overview — из-за отсутствия плана с таким доступом. **Точные top landing pages и количество визитов avtomatika.ru неизвестны**; данное исследование — обоснование SEO-тем и воронки, не отчёт об аналитике конкурента.

## 2. Какие запросы забираем, а какие не трогаем

| Кластер | Доказательство спроса/позиции | Зачем DLV | Тип страницы |
|---|---|---|---|
| RS-485, Modbus RTU, нет связи с ПЛК | «RS-485 простыми» у конкурента в топе, десятки статей по Modbus | Диагностика и интеграция датчиков, приводов, I/O | `/blog/modbus-rtu-rs485-diagnostika/` |
| Modbus 40001, 30001, function 03/04, register offset | У конкурента есть Modbus для новичков, но ошибки адресов — отдельная практическая задача | Исправление программы PLC, интеграция PLC/SCADA | `/blog/modbus-registry-kalkulyator/` с работающим инструментом |
| Сухой контакт, NO/NC, дискретный вход 24 В | Запрос «сухой контакт» у конкурента на 1-й позиции Яндекса | PLC-разработка, диагностика входов и блокировок | `/blog/sukhoj-kontakt-v-plk/` |
| Разработка и доработка PLC/SCADA, Siemens, АСУ ТП | Прямой коммерческий интент; у DLV уже есть страницы услуг | Реальный лид, КП, проект | Существующие URL в `/uslugi/`, без создания дубликатов |
| PLC ↔ MES/ERP/1С, архивы, CIP, OEE | Опыт DLV и релевантные отраслевые задачи | Более дорогие инженерные проекты | Уже существующие коммерческие страницы и кейсы |

**Не приоритетны** запросы домашней автоматизации, дешёвые модули с маркетплейсов, DIY/Raspberry Pi, пользовательские определения «контроллер в компьютере», если они не ведут к промышленным заказам. Каталог оборудования конкурента нельзя «перехватить» одним блогом, пока DLV не торгует этим оборудованием.

## 3. Что выпущено в ветке текущего SEO-спринта

- Три уникальных объясняющих статьи с промышленными сценариями вместо переписывания конкурента.
- Калькулятор 40001/30001 → нулевой адрес PDU, функция 03/04. Работает локально в браузере, без пользовательских данных и сетевых запросов; интерфейс не подменяет документацию изготовителя.
- В статьях есть ссылки на технические источники: Modbus Organization, Texas Instruments, проекты DLV.
- Из статей — ссылки на услуги интеграции оборудования, программирование PLC и диагностику; из пяти коммерческих страниц — обратные ссылки на материалы.
- Новые карточки в `/blog/`; `sitemap.xml` увеличен с 42 до 45 URL. Визуальный дизайн V6 и существующие формы не изменены.

## 5. Что нужно сделать после публикации

1. **P0:** подтвердить HTTP 200 и совпадение 45 URL sitemap с GitHub main на Timeweb, включая калькулятор. Не путать публикацию с индексацией.
2. **P1:** повторно проверить URL Inspection по основным русским услугам и трём новым статьям после того, как Google их обнаружит. Исправлять только диагностированную причину: crawl, canonical, content quality, ссылка, а не менять заголовки каждый день.
3. **P1:** измерять показ/клик/позицию по кластерам `rs 485`, `modbus`, `сухой контакт`, `программирование плк`, `scada`, `modbus plc`. Для отчётов Google учитывать анонимизированные запросы: сумма query-строк может отличаться от общих показов.
4. **P1:** расширить доказанный коммерческий спрос: написать инструкции «Siemens S7-1500 Modbus TCP — диагностика MB_CLIENT», «WinCC/AVEVA InTouch: OPC UA + теги и ошибки» **только после изучения мануалов вендора**; не лепить десятки однотипных определений.
5. **P1/P2:** увеличить ссылочные упоминания через оригинальные полезные материалы (возможные каналы: Хабр, профильные форумы, ОВЕН/партнёрские каталоги). Не отправлять от имени компании ничего без проверки правил площадок, согласования контента и полномочий.
6. **P1:** для России Яндекс потенциально существенен, но в существующем workflow `DLV_YANDEX_ENABLED` намеренно выключен. Не включать втайне; по согласованию пользователя организовать проверку доступов и возобновление загрузки статистики.

## 6. Когда оценивать

7 дней: техническая проверка 45 страниц; факт обхода новых страниц. 14–30 дней: новые поисковые запросы и индекс; 30–60 дней: небрендовые клики, переходы на услуги, обращения в почту. Не обещать численных переходов или позиций без статистики.

**Невозможная на текущих данных претензия:** «у avtomatika.ru точно X посетителей из Google, и Y приходит по Modbus» — достоверных данных нет. SEO-темы и подтверждённые позиции достаточно обоснованы для ограниченного эксперимента, но не для гарантированного прогноза.
