# DLV Automation — бесплатная SEO-автоматизация

**Состояние на 11.10.2026:** исходники и расписания добавлены в публичный репозиторий. Проверка первых фактических запусков GitHub Actions через этот коннектор пока недоступна. Сайт заново регистрировать и подтверждать не нужно.

## Что работает без новых доступов

- `.github/workflows/seo-public-monitor.yml`
  - ежедневно примерно в 08:17 Новосибирска: GET https://dlvautomation.ru/robots.txt, /sitemap.xml и всех URL из sitemap (HTTPS, HTTP, title, H1, canonical, noindex).
  - каждый вторник примерно в 08:47 Новосибирска: проверка 16 публичных страниц конкурентов (несколько страниц одного домена). Соблюдение robots.txt, без обхода ограничений. Сравнение с прошлым публичным artifact, если он ещё доступен.
  - результаты в GitHub Actions → Summary и в artifact (только публичные метаданные).
- При неудачной проверке нашего сайта workflow получает красный статус. Логи и неуспешные проверки смотрятся в Actions.
- При отсутствии доступной предыдущей версии конкурентного среза он становится новым исходным состоянием. Отсутствие доступа к чужому сайту не равно изменению его SEO.

## Сбор закрытой статистики (код готов; автоматическая выгрузка требует API-доступов)

- `.github/workflows/seo-search-analytics.yml` — каждый понедельник примерно в 09:23 по Новосибирску.
- `scripts/seo_search_analytics.py` — только чтение Search Console и Яндекс Вебмастера, запись запросов в **закрытую** Google-таблицу.
- Таблица: https://docs.google.com/spreadsheets/d/14GI6k61MSsqpjFFm9w6fZHTteGhKvKnN3_Hn8o9Gq3k/edit
- Листы: `Google`, `Яндекс`, `Состояние`, `Конкуренты`, `Инструкция`.
- Результаты API не публикуются в репозитории, в публичных логах и artifact.

## Требуется один раз — без повторной регистрации сайтов

### Google
1. В Google Cloud включить **Google Search Console API** и **Google Sheets API** для существующего или нового проекта.
2. Создать service account, выпустить JSON credentials. Содержимое JSON передавать **только в GitHub Actions Secret** под названием `GOOGLE_SERVICE_ACCOUNT_JSON`; никогда не добавлять в код/переписку.
3. Добавить email service account в Google Search Console → «Настройки → Пользователи и разрешения» для ресурса `sc-domain:dlvautomation.ru` или `https://dlvautomation.ru/`. Для чтения данных достаточно пользовательских разрешений.
4. Дать той же service account доступ редактора к указанной **закрытой** Google-таблице.

### Яндекс
1. Для уже подтверждённого в Яндекс Вебмастере ресурса получить OAuth-токен с правом чтения `webmaster:hostinfo` (если действующий токен уже есть, его можно использовать).
2. Сохранить токен **только в GitHub Actions Secret** `YANDEX_WEBMASTER_TOKEN`; не отправлять в чат. OAuth доступ может требовать перевыпуска после истечения срока.

### GitHub
Перейти в **Settings → Secrets and variables → Actions → New repository secret** для репозитория `Rbastl/dlv-automation` и задать ровно два имени:
- `GOOGLE_SERVICE_ACCOUNT_JSON`
- `YANDEX_WEBMASTER_TOKEN`

Google-скрипт должен иметь доступ к закрытой таблице; ID уже записан в workflow. Не добавлять в публичный проект другие OAuth-секреты и личные пароли.

## Проверка запуска
GitHub → Actions:
1. **DLV SEO public monitoring** → Run workflow. Проверить статус проверки сайта и конкурентов, Summary.
2. **DLV SEO private search statistics** → Run workflow. До задания Secrets будет честно писать, что выгрузка не активирована.
3. После передачи доступов запуск повторяют вручную один раз. Затем работают расписания.

## Ограничения
- Не собирается точный трафик конкурентов — это недоступная частная статистика. Сравниваются публичные SEO-страницы и собственные показатели DLV.
- Новые страницы и SEO-правки не публикуются автоматически; нужен просмотр и утверждение.
- Расписания на GitHub Actions могут выполняться с задержкой; в неактивных публичных репозиториях GitHub может отключать schedule после 60 дней без активности.
- Бесплатность касается стандартных публичных GitHub-hosted jobs и обычных API-лимитов. Текущие расходы на домен, Netlify и существующие подписки — отдельно.
