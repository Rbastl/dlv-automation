# DLV Automation — SEO, индексация и публикация (актуально 04.11.2026)

**Контур:** бесплатный органический и реферальный трафик на https://dlvautomation.ru/. Без холодных продаж, коммерческой CRM, платной рекламы и фиктивных кейсов. Утверждённый дизайн **V6 не менять**.

**Источники истины:** GitHub `Rbastl/dlv-automation`, ветка `main` — исходники; Timeweb — единственный production; технические GitHub Pages и старый Netlify не являются боевым сайтом. В `sitemap.xml` на 04.11 — **49 уникальных URL**. Продакшн-публикация подтверждается только независимым HTTPS-чтением и совпадением `/dlv-deploy-revision.txt` с GitHub `main`, а не фактом слияния PR.

**Поисковые системы:** Google Search Console и Яндекс Вебмастер ведутся **параллельно** по решению владельца от 30.10.2026. Старое решение «только Google» отменено. Не отключать Яндекс автоматически. Показатели двух поисковиков не суммировать как одну независимую метрику без нормализованных периодов. Не выдавать пустые данные Яндекса за нулевой трафик.

## 1. Публичный аудит и Timeweb

- `.github/workflows/seo-public-monitor.yml` запускает `scripts/probe_production_https.py` (DNS → TCP/443 → TLS → HTTP) и `scripts/seo_monitor.py --site`. Проверяет `robots.txt`, `sitemap.xml`, коммерческие URL, канонические ссылки и фактическую ревизию Timeweb. Монитор запускается ежедневно около 08:17 по Новосибирску и при изменении его кода. Отдельная задача проверяет публичные страницы конкурентов без обхода robots.
- Сетевой сбой одного GitHub Runner **не доказывает** блокировку Googlebot/ЯндексБота. Равным образом 49/49 HTTP 200 в одном проходе **не доказывает**, что новая ревизия уже опубликована или хостинг стабильно доступен.
- Открытый P0: [issue #43](https://github.com/Rbastl/dlv-automation/issues/43). 03.11 DNS разрешил `dlvautomation.ru` в `92.53.96.223`, однако отдельные проверки из GitHub Runner получили TCP/443 timeout до начала TLS/HTTP. В другое время 49/49 URL отдавали 200 с устаревшим SHA. Причина не установлена; **не менять DNS, firewall и хостинг по догадке**.
- Timeweb поддержка: тикет **№12945785**. Для закрытых проверок поддержка запросила верификацию владельца через контактную почту. Коды, учётные данные, приватные логи и токены нельзя передавать в публичный репозиторий.
- По [официальным инструкциям Timeweb](https://timeweb.com/ru/docs/virtualnyj-hosting/logi-i-statistika/poluchenie-logov/) исторические access/error логи заказывают через панель «Инструменты → Логи», а журналы Cron — через «Поддержка». В [описании форматов](https://timeweb.com/ru/docs/virtualnyj-hosting/logi-i-statistika/chtenie-logov/) прямо сказано, что Apache `access_log` не учитывает существующие статические файлы, обслуживаемые Nginx. При диагностике `robots.txt`, `sitemap.xml`, `dlv-deploy-revision.txt` нужны данные фронтенда/Nginx, TCP/443, WAF/ACL и Cron, а не только Apache.
- [Crontab Timeweb](https://timeweb.com/ru/docs/virtualnyj-hosting/planirovshchik-zadanij-cron/) на виртуальном хостинге настраивается в панели. Проверять время, интерпретатор, результат исполнения `scripts/timeweb_sync_from_github.sh` и наличие актуальной ревизии после Cron. Принудительный сброс lock-файла — только когда подтверждено, что задача не выполняется.

**P0 закрыт только после:** минимум двух разнесённых во времени внешних HTTPS-проверок, `robots`/`sitemap`/коммерческих страниц с 200, 49 уникальных URL, SHA Timeweb = актуальному `main`, и проверки логов/тайм-аутов. До этого не утверждать, что весь боевой сайт обновлён.

## 2. Google: настоящие данные и индекс

- `.github/workflows/seo-search-analytics.yml`: Google-job по понедельникам ~09:23 Новосибирск → `scripts/seo_search_analytics.py`. Google Search Console используется для чтения показов, кликов, CTR, средней позиции. Закрытые вкладки `Сводка`, `Страницы`, `Google`.
- `.github/workflows/google-index-coverage.yml`: URL Inspection по вторникам ~09:47 Новосибирск → `scripts/google_index_audit.py`; пишет в закрытую `Индексация`. API-инспекция индекса отличается от Live Test и **не** отправляет запросы на обязательную индексацию.
- На 03.11.2026: **28 PASS / 49 URL, 21 NEUTRAL**. Коммерческие `/modernizaciya-asu-tp/` и `/outsourcing-asu-tp/` ещё не подтверждены в индексе. Причину выяснять через Live Test, реальную доступность, canonical, внутренние ссылки и логи, а не массовое создание страниц.
- Сравнивать **непересекающиеся** семидневные интервалы (а не недели с общими датами); отдельно считать информационные и коммерческие запросы. Изменение текстов само по себе не доказывает рост трафика.

## 3. Яндекс: отдельный контроль

- Второй независимый job `yandex` в `.github/workflows/seo-search-analytics.yml` запускает `scripts/yandex_webmaster_analytics.py` с токеном только из GitHub Secrets. Подтверждённая HTTPS-собственность и sitemap читаются отдельно от Google; статистика записывается в закрытые вкладки `Яндекс`, `Яндекс — сводка`, `Яндекс — индексация`, если API вернул данные.
- Приоритетный переобход — **только ручной вызов** `workflow_dispatch` и согласие владельца. `504`/timeout не означает успешный POST; повторять отправку вслепую запрещено, сначала читать очередь и квоту.
- На 04.11 достоверная статистика кликов/индексных URL Яндекса в таблице ещё не получена. Не обозначать это как «0 индекса» или «0 реальных посетителей».

## 4. Сайтовые и реферальные работы

- Уже есть страницы PLC/SCADA, Siemens, модернизации, аутсорсинга, пищевого производства, CIP и тестовые инженерные калькуляторы. Новые URL — только если доказан самостоятельный поисковый интент и есть оригинальная техническая ценность.
- Для внешних ссылок сначала Elec.ru (бесплатный профиль с реальными реквизитами и авторизацией владельца), затем ИСУП по ответу редакции. Не покупать массовые ссылки и не подавать ИИ-статьи туда, где редакция запрещает их.
- Отдельно фиксировать результат: URL реально опубликованной карточки, дата, индекс, реферальные переходы, когда есть достоверная аналитика. Нельзя считать «профиль подготовлен» опубликованной ссылкой.
- На сайте пока используются `mailto`-контакты; до реального подключения серверного сбора обращений проверить правовые реквизиты, политику данных и тест доставки, не считать клики по кнопке подтверждёнными письмами.
