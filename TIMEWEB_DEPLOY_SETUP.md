# DLV Automation → Timeweb через GitHub Actions

**Статус:** подготовка нового хостинга, DNS всё ещё должен указывать на прежнюю рабочую площадку до окончательного теста. Не отключать Netlify до подтверждения работы Timeweb.

## Что уже подготовлено

- `.github/workflows/deploy-timeweb.yml` — автоматическая FTPS-публикация после изменений сайта в ветке `main`, а также ручной запуск.
- `scripts/build_timeweb_site.py` — собирает публичные HTML, CSS, JS, favicon, robots, sitemap, файлы подтверждения в `site-dist/`, проверяет все пути в sitemap.
- Не отправляем на хостинг `.github`, `scripts`, `seo`, README и внутреннюю SEO-документацию.
- Учетная запись FTP пользователя создана в Timeweb с ограничением на `dlvautomation/public_html`.
- Путь публикации `server-dir: ./` — **корень FTP для ограниченного пользователя**, а не корень всего аккаунта.

## Три настройки, которые владелец добавляет непосредственно в GitHub

URL: https://github.com/Rbastl/dlv-automation/settings/secrets/actions

| Имя Repository secret | Значение |
| --- | --- |
| `TIMEWEB_FTP_SERVER` | Адрес **FTP-сервера Timeweb** из панели «Дашборд → Доступ по FTP». Не `dlvautomation.ru`, пока домен указывает на Netlify. |
| `TIMEWEB_FTP_USER` | **Полный логин** созданного отдельного FTP-пользователя, включая префикс Timeweb. Скопировать из списка пользователей. |
| `TIMEWEB_FTP_PASSWORD` | Пароль этого отдельного FTP-пользователя. Его не присылать в чат и не записывать в репозиторий. |

Секреты добавляются вручную владельцем проекта. GitHub автоматически маскирует секреты в логах. Повторно создавать FTP пользователя не нужно.

## Порядок перехода без простоя

1. Убедиться, что реальный FTP сервер поддерживает **явный FTP over TLS на порту 21 (FTPS)**. Сценарий строго требует TLS и не переключается на незащищённый FTP.
2. Добавить три `TIMEWEB_FTP_*` Repository secrets по инструкции выше.
3. GitHub → Actions → **DLV publish to Timeweb (FTPS)** → **Run workflow**. Проверить, что `Build safe static website package` и `Publish public files through encrypted FTPS` завершились успешно.
4. Timeweb → Файловый менеджер → `dlvautomation/public_html`: проверить `index.html`, `sitemap.xml`, `uslugi/index.html`, `.htaccess`. Старый `index.htm` пока можно оставить, поскольку `.htaccess` устанавливает приоритет `index.html`.
5. Проверить технический адрес нового хостинга (если предоставляется) либо предварительный просмотр сайта через сервер Timeweb, не меняя публичный DNS. Сверить не только главную, но и вложенные URL.
6. Только после этого сменить A/AAAA/CNAME в Timeweb на реквизиты нового хостинга, **не затрагивая MX/TXT для почты и Google**.
7. Настроить/проверить Let's Encrypt для `dlvautomation.ru` и `www`. Проверить, что `https://dlvautomation.ru/sitemap.xml` отдаёт 40 уникальных URL.
8. Запустить GitHub Actions `DLV SEO public monitoring`; убедиться, что HTML/canonical/SSL без ошибок. Старую площадку отключать только после успешного теста.

## Важные ограничения

- FTP-соединение с пользователем, ограниченным `public_html`, должно иметь корневую директорию `./`; ввод `dlvautomation/public_html/` повторно создаст неправильный вложенный каталог.
- Сценарий **не удаляет всё содержимое FTP-каталога** перед публикацией; устаревшие страницы синхронизируются с помощью состояния загрузки.
- FTP-хост нужно взять именно из панели Timeweb. Использование домена сайта как FTP-хоста до DNS-переключения отправит подключение на Netlify.
- `_redirects` является форматом Netlify; при сборке генерируется `.htaccess` для двух ранее существовавших редиректов и выбора `index.html`.
- Серверная форма заявок требует отдельного решения по фактическому приёму и защите персональных данных. Простое размещение статических файлов не превращает mailto в серверную отправку.
